# 健身计数 App 核心闭环 HTML 原型设计规格

## 1. 目标

使用一个无需构建、打开即用的 HTML 原型，验证健身计数 App 的核心训练闭环、三套主题视觉语言和关键状态反馈，为后续 Flutter 实现提供可复用的布局与设计令牌依据。

原型聚焦个人健身者在训练现场的低注意力操作：快速确认今日内容、开始训练、逐组完成、控制休息、结束并查看总结。

## 2. 范围

### 2.1 本轮包含

1. 今日首页
2. 训练前准备
3. 训练执行
4. 独立休息页
5. 结束训练确认 Bottom Sheet
6. 训练总结
7. A/B/C 三套主题即时切换
8. 核心交互、计时演示、训练组状态变化和页面转场
9. 桌面手机画布与移动端全屏适配
10. 键盘焦点、减少动画和基础无障碍支持

### 2.2 本轮不包含

- 计划列表及计划编辑
- 日历与历史详情
- 动作库
- 完整设置页
- SQLite 或其他真实数据持久化
- 进程回收后的真实恢复
- 通知、震动和系统权限调用
- Flutter 生产代码

主题选择可使用 `localStorage` 保存，仅用于验证原型体验。

## 3. 原型载体

采用单入口、单文件的“手机模拟器”原型：

- 文件：`prototype/fitness-counter/index.html`
- HTML、CSS 和 JavaScript 放在同一文件中，便于直接打开和分享
- 六个屏幕共用一套 DOM 组件和状态模型
- A/B/C 主题只替换 CSS 设计令牌和少量反馈样式，不复制页面
- 桌面端在安静的展示背景中居中显示约 390px 宽 Android 手机画布
- 视口宽度小于 520px 时移除设备外框，应用铺满屏幕

该组织方式只服务本轮视觉和交互评审。扩展到全模块时，再拆分 CSS、状态和页面模块。

## 4. 信息架构与状态流

```text
今日首页
  ├─ 开始今日训练 → 训练前准备 → 开始训练 → 训练执行
  │                                           ├─ 完成本组 → 独立休息页
  │                                           │               ├─ 开始下一组 → 训练执行
  │                                           │               └─ 选择其他组 → 训练执行
  │                                           └─ 结束 → 结束确认
  └─ 主题切换                                      ├─ 返回继续训练
                                                   ├─ 结束并保存 → 训练总结
                                                   └─ 放弃训练 → 今日首页

训练总结 → 完成 → 今日首页（显示今日已完成状态）
```

核心状态：

```text
idle → preparing → active → resting ↔ active → ending → summary → completed
```

训练组状态：

```text
pending | active | completed | skipped
```

结束规则：

- 至少完成一组时，“结束并保存已完成内容”可用
- 零完成组时不生成有效训练记录，保存按钮禁用并解释原因
- 结束时将当前进行组和剩余未开始组标记为跳过
- 放弃训练需要二次确认；确认后清空本次原型会话并回到今日首页

## 5. 页面规格

### 5.1 今日首页

信息顺序：

1. 左侧日期、右侧“今日”页面标签与主题入口
2. 页面标题“今天练什么”
3. 今日训练主卡
4. “开始今日训练”主按钮
5. “自由训练”次入口，仅作展示
6. 累计、本周、本月训练统计
7. 今日动作摘要
8. 底部导航

今日训练主卡显示：

- 训练名称：推力与核心
- 来源：上肢三日循环 · D2
- 预计动作数、总组数和预计时长
- “训练节拍轨道”，展示热身、主训练和收尾三个阶段

完成训练后，主卡变为今日已完成状态，显示训练时长、完成组数和查看总结入口。

### 5.2 训练前准备

显示：

- 来源计划与周期日
- “本次调整不会修改原计划”提示
- 按动作分组的训练清单
- 每组计划重量、次数和目标休息时长
- 动作拖动手柄与组编辑入口，仅作轻量演示
- 固定底部“开始训练”按钮

交互：

- 可修改一组重量或次数，修改后显示“仅本次”标记
- 可折叠动作组
- 点击开始后创建前端内存快照并启动训练总计时

### 5.3 训练执行

顶栏固定显示：

- 返回
- 训练总时长
- 结束

主体显示：

- 完成组数/总组数
- 训练节拍轨道形式的总体进度
- 按动作分组的完整训练组列表
- 计划值与实际值
- 当前组选中和进行状态

底部固定操作：

- 次操作：修改数据、跳过本组、添加组
- 主操作：未开始时为“开始本组”，进行中时为“完成本组”

交互：

- 点击未完成组可切换当前组
- 开始本组后启动单组计时
- 完成本组后记录用时并自动进入休息页
- 跳过后选择下一未完成组
- 状态同时使用图标、文字和形状表达，不只依赖颜色

### 5.4 独立休息页

顶栏继续显示训练总时长和结束按钮。

主体显示：

- 目标休息时长
- 大号实际休息计时
- 环形“训练节拍轨道”
- 距离目标的剩余时间；超过目标后显示“已超过 00:12”
- 下一组动作、重量、次数和组序号
- 后续一组预览

底部操作：

- “选择其他未完成组”
- “结束休息并开始下一组”

规则：

- 进入页面立即开始累计休息时间
- 达到目标时只做一次视觉确认，不自动开始下一组
- 超时后继续累计
- 选择其他组或开始下一组时结束本次休息记录

### 5.5 结束确认

以 Bottom Sheet 覆盖在训练页或休息页上方，背景降低对比度但保持上下文可辨认。

显示：

- 总训练时长
- 已完成动作数
- 已完成组数
- 剩余组数
- 保存有效性说明

操作：

1. 结束并保存已完成内容
2. 返回继续训练
3. 放弃本次训练

Bottom Sheet 的拖拽短条仅表达层级，不实现拖拽关闭；点击遮罩等同返回继续训练，避免误结束。

### 5.6 训练总结

显示：

- 总训练时长
- 完成动作数
- 完成、跳过和未完成组数
- 各动作完成摘要
- 训练备注输入框
- 一条收束后的训练节拍轨道，表达训练完成

主操作为“完成”，返回今日首页并展示已完成状态。总结数据保留在当前浏览器会话中。

## 6. 视觉系统

### 6.1 共同设计原则

- 行动优先：当前最需要执行的动作始终拥有最高视觉权重
- 状态可辨：未开始、进行中、完成和跳过具有文字、图标与形状的复合差异
- 节拍连续：同一个“训练节拍轨道”在不同页面映射计划、进度和休息时间
- 材质克制：每套主题只使用一种主要表面语言，避免所有内容变成同质卡片
- 数据稳定：计时数字使用等宽数字特性，变化时不产生横向抖动
- 文案直接：按钮准确描述点击结果，不使用营销语或模糊词

### 6.2 共同尺寸令牌

```text
画布宽度       390px（桌面）/ 100vw（移动）
页面水平边距   16px
紧凑间距       4px
元素间距       8px
组内间距       12px
区块间距       20px
页面大间距     28px
最小点击区域   48px
底部主按钮高   52px
顶栏高         64px（含安全区后的内容区域）
```

排版层级：

```text
页面主标题       23px / 1.25 / 700
主卡标题         21px / 1.30 / 700
训练总时长       20px / 1.10 / 700
休息主计时       40px / 1.00 / 700
正文             14px / 1.55 / 400
主按钮           14px / 1.00 / 650
动作名称         12px / 1.35 / 650
训练组数据       11px / 1.35 / 500
辅助说明         10px / 1.40 / 400
顶部页面标签     10px / 1.40 / 500
紧凑结束按钮     12px / 1.00 / 700
```

### 6.3 A：呼吸节拍（默认）

颜色令牌：

```text
背景             #F4F7FA
主承载面         #19344C
主操作           #C76F62
进行中/恢复      #62E6CA
主文字           #142A3A
次文字           #60717E
描边             #DFE7EC
卡片表面         #FFFFFF
```

字体：MiSans，回退 `Noto Sans SC`, `Microsoft YaHei`, sans-serif。

形态：

- Hero 圆角 24px，普通表面 14px，按钮 14px
- 只给 Hero 和 Bottom Sheet 使用轻扩散阴影
- 珊瑚色只用于主要行动和完成确认，不作为大面积背景
- 薄荷色只表达进行中、恢复或到达目标

动效：完成组时轨道节点短促扩张后稳定；进行中的轨道只做一次低幅呼吸，不持续循环。

### 6.4 B：训练贴纸册

颜色令牌：

```text
纸张背景         #FFF7D8
训练黄           #FFDF3D
记录紫           #6956DF
盖章红           #FF655F
器械薄荷         #8CE6CF
墨色             #25231E
浅纸面           #FFFDF0
```

字体：得意黑用于页面标题和完成数字；MiSans 用于正文、表单和数据。

形态：

- 主要容器使用 2px 墨色描边
- 普通卡圆角 8px，按钮圆角 10px
- Hero 和主按钮使用 3px 单方向硬阴影，小列表不加阴影
- 进度节点像训练记录章，但不增加无意义贴纸装饰

动效：完成组时节点执行一次轻微旋转和盖章回弹，随后立即静止。

### 6.5 C：夜训仪表

颜色令牌：

```text
夜幕背景         #131720
仪表表面         #1D222C
操作蓝           #5D85FF
状态荧光         #C8FF5A
主文字           #EDF2F7
次文字           #98A4B3
描边             #303845
```

字体：HarmonyOS Sans SC，回退 `Noto Sans SC`, sans-serif；计时使用 Roboto Condensed，回退 `Arial Narrow`, sans-serif。

形态：

- Hero 圆角 20px，普通表面 12px，按钮 12px
- 使用表面明度和细描边建立层级，不使用大面积霓虹外发光
- 荧光色只标记进行中、完成和达到休息目标
- 计时环带有清晰刻度，背景保持静止

动效：状态变化时仅点亮相关刻度；休息环连续更新，但不添加背景运动。

## 7. 标志性元素：训练节拍轨道

训练节拍轨道是本轮唯一重点视觉表达，必须承担信息功能：

- 今日页：显示训练阶段和预计工作量
- 准备页：显示动作及组的顺序结构
- 训练页：显示已完成、当前和剩余训练组
- 休息页：弯曲闭合为休息计时环
- 总结页：收束为完整轨道并标记完成结果

实现上使用 CSS 自定义属性、伪元素和 SVG。SVG 仅负责轨道几何与进度，不嵌入业务文字。所有状态仍提供文本替代说明。

## 8. 动效规范

### 8.1 时长与缓动

```text
微反馈          120–160ms  cubic-bezier(.2,.8,.2,1)
主题切换        180ms      ease-out
页面切换        240ms      cubic-bezier(.22,.8,.25,1)
Bottom Sheet    280ms      cubic-bezier(.2,.9,.2,1)
```

### 8.2 规则

- 首次加载只执行一次整体就位，不逐卡片依次上浮
- 页面切换由轨道和主内容共同完成一次方向明确的过渡
- 用户操作后的动效必须解释“什么状态变了”
- 禁止持续呼吸、漂浮背景、无业务意义粒子和装饰渐变
- `prefers-reduced-motion: reduce` 时取消位移、缩放、旋转和轨道形变，仅保留即时颜色切换

## 9. 交互与演示数据

固定演示计划：

```text
计划：上肢三日循环 · D2
训练：推力与核心
动作：杠铃卧推、哑铃肩推、绳索下压
总组数：9
目标休息：90 秒
```

为方便评审，原型中的计时可以真实按秒更新；休息目标同时提供“跳至目标前 3 秒”的演示控制，该控制仅在桌面展示栏中出现，不进入手机应用 UI。

主题切换放在桌面展示栏；移动端使用右上角调色板按钮打开紧凑主题选择器。选择后立即生效，并写入 `localStorage`。

## 10. 响应式与无障碍

- 主要验证宽度：360px、390px、430px
- 桌面端手机画布最高不超过视口，内容在画布内滚动
- 使用 CSS `env(safe-area-inset-*)` 处理移动端安全区
- 所有可操作元素使用原生 `button`、`input` 或明确语义
- 键盘焦点使用高对比焦点环，不只改变阴影
- 状态不只依赖颜色；提供图标、状态词和 `aria-label`
- 正文及关键控件满足 WCAG AA 对比度
- 计时和动态状态使用克制的 `aria-live="polite"`，避免每秒打断读屏
- 字体放大到 130% 时，计时、组数据和底部操作不可裁切

## 11. 原型代码边界

JavaScript 只负责：

- 屏幕路由
- 训练及单组计时
- 训练组状态
- 休息计时
- Bottom Sheet 与二次确认
- 主题切换与本地保存
- 演示数据修改

不引入 Tailwind 或其他运行时 CDN。原因：本轮视觉高度依赖主题令牌、轨道形变和离线直接打开；原生 CSS 自定义属性更清晰，也避免网络资源阻塞。图标使用内联 SVG，不使用 emoji。

CSS 按层组织，降低选择器冲突：

```text
reset → tokens → themes → layout → components → screens → utilities → motion
```

组件只使用单层 class 选择器；状态通过 `data-theme`、`data-screen` 和 `data-state` 表达，避免深层后代选择器和 `!important`。

## 12. Flutter 映射

HTML 原型与 Flutter 的映射关系：

| HTML 原型 | Flutter 建议 |
|---|---|
| CSS 主题令牌 | `ThemeExtension<FitnessThemeTokens>` |
| `data-theme` | 本地保存的主题枚举 + `ThemeData` |
| 手机屏幕容器 | `Scaffold` + `SafeArea` |
| 固定训练顶栏 | 自定义 `AppBar` |
| 固定底部操作 | `Scaffold.bottomNavigationBar` |
| 训练组列表 | `CustomScrollView` / `SliverList` |
| 结束确认 | `showModalBottomSheet` |
| 训练节拍轨道 | `CustomPainter` |
| 页面状态 | 显式训练会话状态模型 |
| CSS reduced motion | 读取系统动画缩放/无障碍偏好 |

原型评审通过后，Flutter 应复用同一份状态语义和令牌名称，而不是逐像素翻译 HTML。

## 13. 验收标准

1. 直接打开 `index.html` 可运行，无构建和网络依赖
2. 可完整走通“今日 → 准备 → 训练 → 休息 → 训练 → 结束 → 总结 → 今日”
3. A/B/C 主题切换不重置当前训练状态
4. 六个屏幕共享布局和组件，不存在三份主题页面复制
5. 训练总计时、单组状态和休息计时可见且变化正确
6. 零完成组时不能保存有效训练
7. 训练页与休息页始终可触达“结束”
8. Bottom Sheet 支持返回、保存和放弃分支
9. 360–430px 宽度下无横向滚动或关键内容裁切
10. 键盘可操作核心流程，焦点清晰
11. 减少动画模式下无位移、缩放、旋转或持续动画
12. 三套主题均保持状态语义、信息层级和对比度一致

## 14. 设计自检

- 没有使用通用健身落地页常见的渐变 Hero、漂浮装饰或指标卡墙
- A 主题保留已确认的灰调珊瑚色，避免突兀高饱和橙色
- C 主题虽为暗色仪表风，但荧光色严格限制在状态反馈，避免通用霓虹模板感
- B 主题的贴纸感来自描边、硬阴影和盖章反馈，不堆叠无业务含义的贴纸
- 三主题的差异集中在材质和反馈，核心交互与状态语义完全一致
- 视觉大胆点只放在训练节拍轨道，其余结构保持安静、直接和可执行
